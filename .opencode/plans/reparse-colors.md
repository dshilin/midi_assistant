# План: Перепарсинг цветов продуктов

## Проблема

Почему «темный ламинат» не находит товары:

- В `floor_covering_specs.color` у ламинатов цвета: `дуб`, `белый`, `золотой`, `песочный`, `солнечный`, NULL
- Ни один из них не входит в группу `COLOR_GROUPS["темный"]`
- GPT-промпт в `parse_products_gpt.py` разрешал `color: null` — 14 из 31 продукта без цвета
- `COLOR_GROUPS` в `db.py` не включает `дуб` ни в одну группу

## Шаги

### Шаг 1. Обновить GPT-промпт в `app/parse_products_gpt.py`

Изменения:
- Убрать `color: null` из всех примеров
- Добавить список допустимых значений цвета
- Добавить правило: «Поле color ДОЛЖЕН быть заполнен ВСЕГДА. Никогда не ставь null»  
- Добавить fallback по породе дерева: дуб → коричневый, сосна → светлый и т.д.
- В примере 2: `"color": null` → `"color": "серый"` (GREY в названии)
- В примере 3: `"color": null` → `"color": "коричневый"` (дуб → коричневый)

### Шаг 2. Запустить GPT-парсинг для 14 продуктов с NULL/None цветом

```bash
python -m app.parse_products_gpt --ids 853,856,857,858,859,860,862,864,866,867,868,876,877,881
```

### Шаг 3. Обновить `app/migrate_color.py`

- Увеличить приоритет правил для `дуб` → `коричневый` (сейчас нет такого правила)
- Добавить правила: `рыжий` → `коричневый`, `русый` → `коричневый`, `натуральный` → `светлый`
- Убедиться, что `null` (строка) обрабатывается как отсутствие цвета

### Шаг 4. Запустить migrate_color.py

```bash
python -m app.migrate_color
```

### Шаг 5. Обновить `app/db.py` — COLOR_GROUPS

1. Добавить `"дуб"` в группу `"коричневый"`:
```python
"коричневый": ["коричневый", "венге", "шоколадный", "темный", "дуб"],
```

2. Добавить одноуровневое транзитивное расширение в `get_products()`:
```python
# После получения базового набора цветов — расширить подгруппами
_expanded = set(colors)
for c in colors:
    if c in COLOR_GROUPS:
        _expanded.update(COLOR_GROUPS[c])
colors = list(_expanded)
```

Это нужно, чтобы поиск «темный» → находил `коричневый` в группе → а коричневый включает `дуб`.
