# Stock-based availability

## Goal

Показывать и выбирать только товары, которые есть в таблице `stock` с положительным
остатком.

## Scope

Included:
- Поиск товаров в `app/db.py:get_products()` возвращает только товары, у которых
  есть строка в `stock` по артикулу.
- Доступный товар: `products.article = stock.article` и `stock.quantity > 0`.
- Товары без артикула, без строки в `stock`, либо с `quantity <= 0` исчезают из
  поиска.
- Получение товара по ID в `get_product_by_id()` применяет то же правило, чтобы
  расчёт не проходил для недоступного товара.
- В результатах можно вернуть `stock.quantity AS stock_quantity` для отладки и
  будущего отображения.

Not included:
- Изменение FSM-сценария диалога.
- Отображение остатка пользователю.
- Fallback на старый фильтр каталога `in_stock-is-y`.
- Сопоставление товаров по названию, если артикула нет.

## Architecture

Таблица `stock` становится единственным источником доступности. Каталог и GPT-спеки
по-прежнему дают описание товара, но доступность определяется только складским
остатком.

```text
products + floor_covering_specs + stock(quantity > 0)
        -> db.get_products()/get_product_by_id()
        -> agent_fsm
```

## Components

### `app/db.py:get_products()`

Добавить `INNER JOIN stock st ON st.article = p.article AND st.quantity > 0`.
Остальные фильтры по типу, бренду и цвету остаются без изменений.

### `app/db.py:get_product_by_id()`

Добавить такой же `INNER JOIN stock`, чтобы выбранный ранее товар считался
валидным только пока он есть на складе.

## Error handling

Если таблицы `stock` нет, запрос упадёт как обычная ошибка БД. Это нормально:
после перехода на складские остатки загрузка `stock` через `python -m app.load_stock
<xlsx>` обязательна.

## Testing

Добавить минимальный тест `tests/test_db.py` или расширить существующий тест БД:
- товар с `stock.quantity > 0` возвращается;
- товар без строки в `stock` не возвращается;
- товар с `stock.quantity <= 0` не возвращается;
- `get_product_by_id()` не возвращает недоступный товар.

## Notes

- `INNER JOIN` намеренно убирает все товары без артикула или без строки в `stock`.
- Сопоставление по названию не добавляется: это риск ложных совпадений.
